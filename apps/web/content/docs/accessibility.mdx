## Reduced motion

When the system setting `prefers-reduced-motion: reduce` is on, Keyframery uses short fades or instant swaps:

- nothing moves, scales or blurs
- fades last between about 120 and 160 ms
- the page doesn't sink behind sheets and drawers
- no toasts flying from the button you pressed
- [ValueCut](/docs/helpers/value-cut) swaps the value instantly
- [LoadCut](/docs/helpers/load-cut) still waits before showing a skeleton, so it doesn't flash, then fades
- [StateCut](/docs/helpers/state-cut) uses opacity only, without slide or height motion

You don't need to do anything for this. It's on for everyone who asks their system for less motion.

To check it, open Chrome DevTools, then **Rendering**, then **Emulate CSS media feature prefers-reduced-motion**.

## Focus and keyboard

Keyframery never moves focus and never adds focusable elements. Opening, closing and focus trapping stay with Base UI or Radix, exactly as in stock shadcn. Keyboard presses count as the start of a cut just like clicks, so a dialog opened with Enter grows from the focused button.

## Screen readers

- Ghosts, the copies Keyframery animates when something leaves, are `aria-hidden` and ignore the pointer.
- ValueCut's rolling digits are `aria-hidden`. A visually hidden copy always holds the current value. Add `announce` to read changes out with `aria-live="polite"`.
- LoadCut sets `aria-busy` while loading.
- StateCut's outgoing snapshot is `aria-hidden` and inert, so it cannot duplicate interactive or screen-reader content. StateCut does not move focus or announce its new view; add the appropriate focus handling or status announcement for your app's workflow.
