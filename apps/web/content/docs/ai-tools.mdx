A coding agent can install Keyframery and pick the right cut for each change in your app. Claude Code gets a plugin with a skill that already knows the rules. Any other agent reads the same docs as plain Markdown.

You need an existing React project with shadcn/ui configured to install the components. Base UI and Radix are both supported; see [installation prerequisites](/docs/installation) and [tested versions](/docs/compatibility#tested-versions).

## Claude Code plugin

The plugin adds one skill. It tells Claude how to install Keyframery, which cut fits each kind of change, and where the Markdown docs live when it needs a helper's exact props. In Claude Code, run:

```bash
/plugin marketplace add keyframery/keyframery
/plugin install keyframery@keyframery
```

Then ask for what you want, for example "add Keyframery to this app" or "animate the inbox list".

The skill is also published at [`/.well-known/agent-skills/keyframery/SKILL.md`](/.well-known/agent-skills/keyframery/SKILL.md), so agents that load skills from a URL can use it too.

## Copy a prompt

No plugin needed. The home page has a **Copy for your coding agent** button that puts the full setup on your clipboard: the install command, where `<Cuts />` goes, and which helper to use for lists, numbers, loading and state changes, each with its docs link. Paste it into Codex, Cursor or any chat.

If you have tuned a motion theme, copy the agent prompt from the [theme builder](/theme) instead. It carries your exact settings, so the agent applies the theme you chose rather than an approximation.

## Any other agent

Codex, Cursor, VS Code (GitHub Copilot), Gemini CLI and other agents can read the docs straight from the site:

| URL | What it has |
|---|---|
| [`/llms.txt`](/llms.txt) | an index of every page, with one line each |
| [`/llms-full.txt`](/llms-full.txt) | every page in full, in one file |
| any docs page + `.mdx` | that page as Markdown, for example [`/docs/helpers/list-cut.mdx`](/docs/helpers/list-cut.mdx) |

Paste `https://keyframery.com/llms.txt` into a chat, or add a line to your project rules so the agent knows where to look. Codex and most other agents read `AGENTS.md`; Claude Code reads `CLAUDE.md`.

```md title="AGENTS.md"
This project uses Keyframery for motion. Docs index: https://keyframery.com/llms.txt
Read a page as Markdown by adding .mdx to its URL before using a helper.
Use ListCut for lists that change, ValueCut for numbers and statuses that change,
LoadCut for skeletons, StateCut for whole-content state switches,
and MatchCut for a card that opens into a detail view. Keep one root <Cuts />.
Use the chosen motion theme's Cuts props and CSS variables.
Avoid duplicating animations on supported parts already handled by Keyframery.
```

## Try one concrete agent task

Open your app repository and ask:

```text
Add Keyframery to this existing shadcn/ui app. Start from
https://keyframery.com/llms.txt, then read installation.mdx,
components/dialog.mdx and helpers/list-cut.mdx under https://keyframery.com/docs/.
Check whether this project uses Base UI or Radix before composing triggers.
Keep one root <Cuts /> and preserve the current dialog's accessible title,
description and focus behavior. Animate the release checklist with ListCut:
keep stable item ids and support add, remove and reorder.
Use the installed component APIs, keep reduced-motion support, and run the
project's existing checks. Report the files changed and how to try the result.
```

For a smaller change, ask for just the [dialog opening from its trigger](/docs/components/dialog#working-example-review-a-release) or the [add/remove/reorder checklist](/docs/helpers/list-cut#working-example-a-release-checklist). The docs are reference material; the agent still needs to look at your app and check its own changes.

If the shadcn CLI reports an unknown `@keyframery` registry, use the [registry fallback](/docs/installation#if-the-dialog-still-pops-into-the-middle).
