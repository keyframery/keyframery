Choose by the interaction you need and the code you want to own. Keyframery adds a root motion layer to supported shadcn/ui components. Motion gives you an API for custom animation. Animate UI v2 installs animated primitives behind your existing components. Magic UI provides components and visual effects to add, while tw-animate-css supplies CSS animation utilities.

## At a glance

| | Keyframery | Motion | Animate UI | Magic UI | tw-animate-css |
|---|---|---|---|---|---|
| What it is | A motion layer for supported shadcn/ui parts | An API for custom React and JavaScript animation | Animated primitives for Radix UI, Base UI and React Aria | Components and visual effects to add | Tailwind CSS animation utilities |
| How you use it | Install copied source, render `<Cuts />` once, and use focused helpers for your own markup | Write animations with `motion` components and props | Install `@animate-ui/react` and `motion`; the CLI can update primitive imports across installed components | Install or copy individual components | Apply classes such as `animate-in` and `fade-in-0` |

## When to use Keyframery

When you want the app you already have to move well, without rewriting it: dialogs that grow from the button you pressed, sheets that slide in while the page steps back, tabs that slide, toasts from the button that made them, and lists, numbers, loading states, cards and whole views that change without jumping. It's one consistent motion theme across the whole app: start from Quiet, Crisp or Expressive in the [theme builder](/theme). You can tune the result with [CSS variables and props](/docs/customize).

## When to use Motion

When you need animation that you design yourself: gestures and dragging, scroll-linked effects, springs, SVG, or a one-off sequence for a landing page. Keyframery doesn't try to replace a general animation library. It covers the everyday changes in an app, so you don't have to write them.

## When to use Animate UI or Magic UI

Animate UI v2 fits projects that want motion inside their primitive layer. Its CLI changes the imports in existing shadcn/ui files and removes animation classes that Motion replaces. It also provides agent workflows. Review its dry run to see the changes before applying them.

Magic UI fits a page that needs a selected effect or component, such as an animated list or visual accent. Review each example's dependencies and behavior. Keyframery focuses on a shared motion theme for supported app interactions and five helpers for changes in your own markup.

## About tw-animate-css

It's probably already in your project: shadcn/ui uses its classes for the default fades and zooms. For the components Keyframery covers, its cuts take over from those classes while `<Cuts />` is in your layout. Everything else keeps its tw-animate-css animation. If shadcn's own animations don't work at all, see [Animations not working](/docs/guides/animations-not-working).

## Can I use them together?

Yes. Keyframery animates its supported shadcn/ui parts, which it finds by their `data-slot` names, and elements you wrap in its five helpers.

- Use each animation system on separate elements. A component from another library may retain shadcn's `data-slot` names, so Keyframery can still recognize it.
- For a supported shadcn part with its own animation, add `data-cut="none"` to opt it out of Keyframery. Check opening, closing and reduced-motion behavior after combining systems. See [Customize](/docs/customize#one-element-or-one-area).
- Start with the [installation guide](/docs/installation) and [compatibility table](/docs/compatibility) to check what the root layer covers.
