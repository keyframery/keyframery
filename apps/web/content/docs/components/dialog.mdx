To animate a shadcn/ui dialog opening and closing, render one `<Cuts />` in your app root and keep using your existing `Dialog`. The default animation grows the dialog from the button that opened it and returns it there on close. Base UI and Radix are both supported.

## Working example: review a release

Start with a React project that already has shadcn/ui and its global stylesheet configured. Install the motion layer and dialog:

```bash
npx shadcn add @keyframery/cuts
npx shadcn add dialog
```

Render `<Cuts />` once in your root layout. Keep your existing providers, styles and fonts; this is the minimal Next.js App Router version:

```tsx title="app/layout.tsx"
import type { ReactNode } from "react"
import { Cuts } from "@/components/keyframery/cuts"
import "./globals.css"

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Cuts />
      </body>
    </html>
  )
}
```

Then add this component to a page. It uses the trigger's own button, so the same example works with either shadcn base:

```tsx title="components/release-dialog.tsx"
"use client"

import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@/components/ui/dialog"

export function ReleaseDialog() {
  return (
    <Dialog>
      <DialogTrigger className="rounded-md border px-4 py-2">
        Review release
      </DialogTrigger>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>Release ready for review</DialogTitle>
          <DialogDescription>
            Check the changelog and preview before publishing.
          </DialogDescription>
        </DialogHeader>
        <ul className="list-disc pl-5 text-sm">
          <li>Changelog complete</li>
          <li>Preview checked</li>
        </ul>
        <DialogFooter>
          <DialogClose className="rounded-md border px-4 py-2">
            Back to editing
          </DialogClose>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  )
}
```

Open **Review release**, then close with **Back to editing** or Escape. The dialog should grow from the trigger and return to it. The dialog base still handles focus, keyboard input and its accessible title and description.

For Vite, React Router or an unknown registry error, follow the [root setup and registry instructions](/docs/installation). You do not need Motion or Framer Motion for this animation.

## Base UI, Radix and limits

- Keep `data-slot="dialog-content"` on the popup. Older or heavily customized shadcn copies may need that attribute restored; check the [compatibility versions](/docs/compatibility#tested-versions).
- To compose a shadcn `Button`, Base UI uses `<DialogTrigger render={<Button />}>Review release</DialogTrigger>`; Radix uses `<DialogTrigger asChild><Button>Review release</Button></DialogTrigger>`. Do not put a button inside the trigger's default button.
- A dialog opened by code without a recent press starts from the center. Set `data-cut-origin="center"` if that is always the effect you want.
- Keep `<Dialog>` mounted while closing. Removing the whole component immediately prevents its exit animation; see [fixing interrupted closing animations](/docs/guides/animations-not-working#the-closing-animation-is-cut-short).
- With the system's reduced-motion preference, the dialog fades without movement, scaling or blur. See [motion accessibility](/docs/accessibility).

## Which cut it uses

Dialogs use the **Rack focus** cut. A cut is how something arrives on the screen and how it leaves. With rack focus, it grows out of the button you pressed, a little soft, and sharpens in place, the way a camera pulls focus. Closing goes back into the button. There are 3 to pick from, and each one is a single prop:

<CutCards menu="dialog">

| Cut | What you see | Code |
|---|---|---|
| Rack focus (default) | Grows out of the button you pressed, a little soft, then sharpens. Closing goes back into the button. | `<Cuts dialog="rack-focus" />` |
| Punch in | Pops up in the middle with a tiny bounce. Closing shrinks it away. | `<Cuts dialog="punch-in" />` |
| Fade | Fades in where it stands. Nothing moves. | `<Cuts dialog="fade" />` |

</CutCards>

## What it fixes

A stock dialog appears in the middle of the screen, unconnected to what you pressed. With Keyframery it starts out toward the button, slightly small and soft, and sharpens in place. That's a rack focus: the camera pulls focus from the page to the dialog. Closing reverses it, back into the button.

## Change it

Every change is one prop. The controls at the top of the page try them live.

### Change just one

The `dialog` prop changes every dialog, alert dialog and command menu. For just one dialog, put `data-cut` on its `DialogContent`:

```tsx
<DialogContent data-cut="fade" />
```

### Grow from the middle

A rack focus starts at the button you pressed. To start from the middle of the screen instead:

```tsx
<DialogContent data-cut-origin="center" />
```

A dialog opened from code, with no press, has no button to grow from, so it starts from the middle anyway.

### Make it faster or slower

`pace` multiplies every duration: `1.6` is slower, `0.6` is faster.

```tsx
// In your root layout: every motion in your app
<Cuts pace={1.6} />

// Or just this one
<DialogContent data-cut-pace="1.6" />
```

### Turn it off

```tsx
// In your root layout: no motion on any dialog
<Cuts dialog="none" />

// Just this one keeps shadcn's own motion
<DialogContent data-cut="none" />
```

With reduced motion turned on in the system settings, movement becomes a short fade or nothing.

## Props

**On `<Cuts />`**, in your root layout:

| Prop | Values | Default | What it does |
|---|---|---|---|
| `dialog` | `"rack-focus" \| "punch-in" \| "fade" \| "none"` | `"rack-focus"` | The cut for every dialog, alert dialog and command menu. |
| `pace` | `number` | `1` | Multiplies every duration in your app. |

**On one `DialogContent`**, for just that one:

| Prop | Values | Default | What it does |
|---|---|---|---|
| `data-cut` | `"rack-focus" \| "punch-in" \| "fade" \| "none"` | – | The cut for this one. Beats the `<Cuts>` prop. |
| `data-cut-origin` | `"center"` | – | center: a rack focus starts from the middle instead of the button. |
| `data-cut-pace` | `number` | `1` | Multiplies every duration of this one. |

**In your global CSS:**

| Prop | Values | Default | What it does |
|---|---|---|---|
| `--kf-ease` | `string` | `cubic-bezier(0.22, 1, 0.36, 1)` | The curve things arrive on. Or pick a theme at [/theme](/theme). |
| `--kf-ease-exit` | `string` | `cubic-bezier(0.5, 0, 0.75, 0)` | The curve things leave on. |

## Timing

| Cut | Opening | Closing |
|---|---|---|
| `rack-focus` | from 35% toward the opener, at 0.94 scale and 8px blur, 340 ms | back toward the opener, 220 ms |
| `punch-in` | from the centre, 0.85 to 1.02 to 1, 260 ms | to 0.96 and fade, 160 ms |
| `fade` | opacity only, 200 ms | 150 ms |
