**Use tw-animate-css on Tailwind CSS v4, and tailwindcss-animate only on a Tailwind v3 project.** Both give you the same enter and exit utilities (`animate-in`, `fade-in`, `zoom-in-95`, `slide-in-from-top-2` and their `out` versions); they differ in how they plug into Tailwind.

| | tw-animate-css | tailwindcss-animate |
| --- | --- | --- |
| Tailwind version | v4 | v3 |
| How it's added | `@import "tw-animate-css";` in your CSS | `plugins: [require("tailwindcss-animate")]` in `tailwind.config.js` |
| Used by new shadcn/ui projects | Yes | No (older projects) |
| npm downloads, week to 14 Nov 2026 | 49.8 million | 23.7 million |

Download counts are from the [npm registry API](https://api.npmjs.org/downloads/point/last-week/tw-animate-css).

## Switch from tailwindcss-animate

1. Remove the plugin from `tailwind.config.js` and uninstall it.
2. Install the new package:

```npm
npm install tw-animate-css
```

3. Import it after Tailwind in your global stylesheet:

```css title="app/globals.css"
@import "tailwindcss";
@import "tw-animate-css";
```

Your existing `animate-in` and `animate-out` classes keep working.

## "Can't resolve 'tw-animate-css'"

The stylesheet imports the package but the project doesn't have it. Install it as above and restart the dev server. In a monorepo, install it in the app that owns the stylesheet, not only at the root.

## With UI SDK, prefer transitions

The tw-animate-css classes in shadcn/ui examples are keyed to Radix's `data-state="open"` and `data-state="closed"`. UI SDK uses different attributes: a popup, dialog or panel gets `data-starting-style` on its first frame and `data-ending-style` while it leaves, and UI SDK keeps it mounted until the exit **transition** finishes. So for UI SDK, a CSS transition on those two attributes is the dependable way to get both the entrance and the exit:

```css
[data-slot="menu-content"] {
  transform-origin: var(--transform-origin);
  transition: opacity 150ms, scale 150ms;
  &:is([data-starting-style], [data-ending-style]) {
    opacity: 0;
    scale: 0.95;
  }
}
```

The full tested set (menus, dialogs, tabs, collapsible panels, reduced motion) is in [What is Vercel's UI SDK, and how do you animate it?](/blog/what-is-vercel-ui-sdk). Keyframery's [63 animated UI SDK components](/docs/components) are built the same way, so they need neither tw-animate-css nor tailwindcss-animate. If something still won't move, see [UI SDK animations not working](/docs/guides/animations-not-working).
