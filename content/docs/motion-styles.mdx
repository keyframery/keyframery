A motion style changes how everything moves: how fast, how springy, and how much flourish. Keyframery is quiet by default: Subtle reads like shadcn/ui, and the expressive styles are one attribute away. Try them here. The switcher changes this whole site.

<MotionStylePlayground />

| Style | Speed | Feel | Good for |
| --- | --- | --- | --- |
| **Subtle** | 0.7× (quick) | Fades and short slides, no bounce, no flourishes. The default | Any product; reads like shadcn/ui |
| **Calm** | 1.35× slower | No bounce; moves settle softly | Dashboards, finance, long sessions |
| **Springy** | 1× | A 5% spring, a 16% pop and every flourish | Products that want motion to be part of the brand |
| **Snappy** | 0.6× (faster) | Crisp, almost no overshoot | Developer tools, dense apps |
| **Playful** | 1.15× | A 12% spring and a 29% pop | Consumer apps |

## Set a style

Put `data-motion` on `<html>`. Popups render at the end of `<body>`, so setting it on `<html>` makes sure they follow too. Leave it off for Subtle.

```html
<html data-motion="calm">
```

## Let people choose

The switcher is a component like the others. It applies the style to the page and remembers the choice.

```npm
npx shadcn@latest add @keyframery/motion-style
```

```tsx
import { MotionStyleSwitcher } from "@/components/keyframery/motion-style"

export function Settings() {
  return <MotionStyleSwitcher />
}
```

## How it works

Every duration in every component is written as a multiple of one variable, and every easing reads one of three tokens:

```css
/* inside a component */
transition: scale calc(260ms * var(--kf-speed, 1)) var(--ease-pop);
```

| Token | What it is | Used for |
| --- | --- | --- |
| `--kf-speed` | A multiplier for every duration and delay | The overall pace |
| `--ease-house` | A smooth ease-out, no overshoot | Fades, heights, stretches |
| `--ease-spring` | A spring with a small overshoot | Moves and entrances |
| `--ease-pop` | A livelier spring | Small payoffs: a check landing, a press releasing |

A style is new values for those tokens. The springs are written with CSS `linear()`, so nothing runs in JavaScript.

## Flourish

Some motion tells you what happened: a menu fades in, a tab indicator slides to the tab you picked, a switch thumb travels. Some is flourish: the indicator stretching as it goes, a check drawing itself, numbers rolling, an error field shaking, rows cascading in when a page loads. Every flourish is scaled by one more token, `--kf-flourish`:

| Value | What you get | Set by |
| --- | --- | --- |
| `0` | Feedback only. The new state still shows (the number, the check, the red error), it just doesn't perform | Subtle |
| `1` | Every flourish at full size | Calm, Springy, Snappy, Playful |

Anything in between works too, so `--kf-flourish: 0.5` gives half-size stretches and pops. Like the other tokens, it can be set on any element.

## Make your own

```css
[data-motion="brand"] {
  --kf-speed: 0.85;
  --kf-flourish: 0.5; /* half-size stretches and pops */
  --ease-spring: var(--ease-house); /* no overshoot on moves */
}
```

Then use `data-motion="brand"`.

## Nesting

`data-motion` works on any element, so one part of an app can move differently from the rest:

```tsx
<html data-motion="calm">
  …
  <section data-motion="playful">{/* onboarding */}</section>
</html>
```

Popups opened from inside the section render at the end of `<body>`, so they follow the style on `<html>`.
