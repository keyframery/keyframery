## 3.1: Keyframery for Vue

November 2026

Every Keyframery component now comes for Vue 3 and Nuxt, built on UI SDK for Vue: the same parts with the same names, the same Tailwind classes, the same five motion styles and the same [Agent view](/docs/agent-view).

- **Install with the shadcn-vue CLI.** `npx shadcn-vue@latest add https://keyframery.com/r/vue/tabs.json` copies the component into `components/keyframery/`, one file per part, and adds the motion tokens to your CSS. Add `@keyframery` to `components.json` once and it's `npx shadcn-vue@latest add @keyframery/tabs`. [Install for Vue](/docs/installation/vue) covers Vite and Nuxt.
- **Every component page has React and Vue code.** Installation, Usage and every example switch together, and the docs remember your pick.
- **Written for Vue, not wrapped.** Props in kebab-case, `v-model`, scoped slots for state and `#render` for React's `render` prop. Every part is typed with UI SDK's own props, so your editor completes them and `vue-tsc` catches mistakes.
- **Checked against React.** Every one of the 337 React examples has a Vue version, and a test bench compares the two in the browser, element by element, in Subtle and Springy. The components pass the `vue-ts` template's strict build and render in Nuxt on the server without hydration mismatches.

**Smaller changes**

- **Accordion** keeps text with a value in it, like `Fill in your {step} here.`, as one paragraph.

## 3.0: Quiet by default, sheets on phones

November 2026

Keyframery 3.0 is the component library for UI SDK that fits any product: calm out of the box, with the springs one attribute away, and popups that become sheets on phones.

**Motion is a dial now**

- **Subtle is the new default.** It moves about as much as shadcn/ui: quick fades and slides, no bounce. [Calm, Springy, Snappy and Playful](/docs/motion-styles) turn the motion up with one `data-motion` attribute, and every switcher on the site starts at Subtle.
- **A new token, `--kf-flourish`, scales every flourish** in all 89 components: stretches, pops, press scales, rolling numbers, drawn checks, shakes and the cascades that play when content appears. It is `0` in Subtle and `1` in the four expressive styles; anything in between works for your own style. The state itself (the new number, the check, the red error) always shows.
- **To keep the springy motion you had,** put `data-motion="springy"` on `<html>`. It looks exactly as before: we compared every component against 2.x frame by frame.
- **[Create](/create)** starts from Subtle, and every preset code you have shared keeps the motion it was made with.

**Popovers on desktop, sheets on phones**

- **Popover, Menu, Select, Combobox, Autocomplete and Date Picker** now open as a sheet from the bottom of the screen on small touch screens and stay popovers everywhere else. This is UI SDK's `presentation="auto"`, now the default; pass `presentation="popover"` to keep one floating everywhere.
- **Every popup is styled as a sheet,** Dialog included (`presentation="sheet"` or `"auto"`): full width, a grip, room for the home indicator, and for Combobox and Autocomplete the search field moves into the sheet's header.
- **Combobox and Autocomplete** gain a Presentation control in Customize, like the others.

**UI SDK 0.1.0-beta.17**

- **Built and tested on UI SDK `0.1.0-beta.17`.** The registry pins it, so adding a component brings a project up to beta.17: six releases of fixes, and agents that can find a component on another tab, page or closed section.

**Smaller changes**

- **Segmented Control** takes `--segmented-control-item-padding`, so a control with many items fits a narrow space.

## UI SDK 0.1.0-beta.9

November 2026

- **Built and tested on UI SDK `0.1.0-beta.9`.** The registry pins it, so adding a component brings a project up to beta.9.
- **Dialog and Popover take `inline`.** The content (and a dialog's backdrop) renders where it sits in the page instead of the top layer, so it can stay inside a frame.
- **Controllers can move the highlight.** Combobox, Autocomplete and Listbox controllers take `highlight(value)` and `getHighlighted()`.
- **Pagination takes `disabled`**, which turns off every page and step at once.
- **Autocomplete's `onValueChange` tells suggestions apart.** Its details carry the chosen `item`, typed as `AutocompleteValueChangeDetails`.
- **Safer agent actions.** An agent that removes an item marked `data-agent-confirm` now needs a person's OK, as adding one already did.

## Customization, UI SDK core and clearer docs

November 2026

- **82 components, all built on UI SDK.** Additional components use `definePrimitive` on UI SDK's core, with the React adapter for their rendered parts.
- **Customize below every preview.** Colors, sizes, content and behavior controls are open by default. Animation speed is separate from the four motion styles; 1× is normal and higher is faster.
- **State callbacks and exports preserved.** Both primitive and styled imports retain UI SDK exports and state-based `className`, `style`, `children` and `render` support.
- **Searchable docs.** Filter components by category, follow related components and inspect documented CSS theme variables. Theme colors remain unchanged until overridden.

## 2.0: Every UI SDK component, on 0.1.0-beta.5

November 2026

Keyframery now has an animated version of every UI SDK component, all 55, and each one takes everything its UI SDK counterpart takes. With the 8 components UI SDK doesn't have, that makes 63.

- **Preferences** is new, the last UI SDK component Keyframery was missing. It comes with `PreferenceSwitcher`, a segmented control for any preference. The motion style switcher is built on it.
- **Built and tested on UI SDK `0.1.0-beta.5`.** The registry pins that version.
- **Every UI SDK part, prop and helper works from both layers.** The finished components gain `TabsTabIcon`, `TabsIndicator` and `CommandItems`, and pass through every controller (`createTabsController` and the rest), `confirm`, `sheetPhysics` and the tree helpers. Parts that add an element of their own (a chevron, the moving key) now take `children` as a function of their state too.
- **Menus, listboxes and command lists written as data** (`items`) render with Keyframery's rows. A data menu renders its own content, as in UI SDK.
- **Menu handles context menus by itself.** A Menu that opens from a `MenuContextTrigger`, as in UI SDK, unfolds from the pointer. Context Menu is still there under its own name.

## 1.3: Speed, Table and fuller docs

November 2026

- **`speed` on every component.** Pass `speed="fast"`, `"slow"` or a multiplier like `0.8` to change how fast one component moves, popups included. `KeyframeryProvider` sets it, and the motion style, for a whole app. Both come from a new shared file, `lib/keyframery.tsx`, installed with the motion tokens.
- **Table**, the 62nd component, with shadcn's part names. Rows cascade in, a sortable header's arrow turns over on a spring, selected rows fade in, and a wide table scrolls sideways on a phone with a soft edge.
- **Sidebar highlight is quicker:** the key now glides to the item you click in 260ms instead of 460ms.
- **Every component page has more to it:** a short usage snippet, how the parts fit together, small live examples you can open as code, a props table for each part (read from the types), a keyboard table, and manual install steps next to the CLI.

## 1.2: Phone layouts

November 2026

- **Every demo has a phone layout.** Demos are fluid and respond to their own width with container queries, so on a phone they rearrange instead of shrinking. The navigation menu turns into a breadcrumb and a menu button, panels stack, and keyboard hints step aside.
- **Sidebar sheet:** below `mobileBreakpoint` (640px by default) the sidebar slides in over the page, over a scrim. The trigger opens it, and the scrim, Escape or choosing a page closes it. `useSidebar()` now also returns `isMobile`, `openMobile` and `setOpenMobile`.
- **Mobile preview in the docs:** each component page can show its demo at a phone's width, next to the desktop view.

## 1.1: Sidebar

November 2026

- **Sidebar**, the 61st component. UI SDK has no sidebar, so it uses shadcn's part names on plain elements, like Card. The current page's key glides between items, groups fold away with the collapsible's height, and the whole sidebar narrows to an icon rail.
- **Demos use real photos** in place of drawn stand-ins.

## 1.0: Keyframery for UI SDK

November 2026

Keyframery is now a set of animated components for [UI SDK](https://ui-sdk.dev).

- **60 components**, each built on its UI SDK counterpart with the same parts and props.
- **Two layers per component:** a primitive that adds motion only, and a finished component with a look.
- **Four motion styles:** Calm, Springy, Snappy and Playful, switched with `data-motion`.
- **Plain CSS:** no animation library. Springs are CSS easings.
- **Installs with the shadcn CLI** from the `@keyframery` registry.
- **A skill for Claude Code** and a prompt for other coding agents.

### If you used the earlier Keyframery

The earlier Keyframery was a motion layer for shadcn/ui, built around a `<Cuts />` component. It has been retired, and its registry items (`cuts`, `value-cut`, `list-cut`, `load-cut`, `state-cut`, `match-cut` and `icon-moves`) are no longer served. The code already copied into your project keeps working, because the shadcn CLI copies source rather than linking to it.
