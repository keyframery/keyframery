[UI SDK](https://ui-sdk.dev) is a headless component library. It gives you correct, accessible behaviour (keyboard, focus, positioning, screen readers) and leaves the look and the motion to you. New to it? Read [what Vercel's UI SDK is and how it works](/blog/what-is-vercel-ui-sdk).

Keyframery fills in the motion. Tabs stretch toward the tab you pick, menus unfold from the button that opened them, checks draw themselves and numbers roll. Nothing about UI SDK's behaviour changes.

## Two layers, so you take what you need

Each component is two files:

```text
components/keyframery/
├── primitives/tabs.tsx   UI SDK's Tabs with motion. Same parts, same props, no styling.
└── tabs.tsx              The finished component: our look, built on the primitive.
```

- **The primitive** is a drop-in for the UI SDK import. It adds motion and nothing else, so your classes, colours and spacing stay yours. See [Swap the import](/docs/swap-the-import).
- **The finished component** adds a look on the shadcn/ui colour tokens, so it fits a shadcn project out of the box. See [Theming](/docs/theming).

## What you get

| | |
| --- | --- |
| **60 components** | From Accordion to Waterfall. [See them all](/docs/components). |
| **Four motion styles** | Calm, Springy, Snappy and Playful change how everything moves with one attribute. [Motion styles](/docs/motion-styles). |
| **Plain CSS** | No animation library. The motion runs in CSS and works in server-rendered pages. |
| **Your code** | The shadcn CLI copies the source into your project. It is yours to change. |
| **Accessible** | UI SDK's keyboard and screen-reader behaviour, untouched. Reduced motion is respected. [Accessibility](/docs/accessibility). |
| **Agent-ready** | A skill for Claude Code and a prompt for any other coding agent. [Use with AI tools](/docs/ai-tools). |
